# 2. 두 배 — A일지도?

정수 N개로 된 수열 A[1], A[2], …, A[N]이 있다. 각 값은 양수일 수도, 음수일 수도 있다.

이 수열의 합을 **2N 이상**으로 만들고 싶다. 한 번의 작업에서는 번호 i(1 ≤ i ≤ N)를 하나 골라 A[i]를 `max(A[i] + i, i)`로 바꾼다. 즉 A[i] + i와 i 중 큰 값으로 바꾼다. 단, 같은 번호에는 작업을 한 번까지만 할 수 있다.

### 예시 (입력 예의 테스트 케이스 #1)

```
5
2 -3 0 1 -1
```

처음 합은 2 − 3 + 0 + 1 − 1 = −1이고 목표는 2N = 10이다.

- A[5]에 작업하면 max(−1 + 5, 5) = 5가 되어 합이 6 늘어난다.
- A[2]에 작업하면 max(−3 + 2, 2) = 2가 되어 합이 5 늘어난다.
- 두 번 작업하면 합이 −1 + 6 + 5 = 10으로 목표에 닿는다. 한 번으로는 가장 크게 늘려도 5라서 모자란다.

따라서 최소 작업 횟수는 **2**이다. 처음부터 합이 2N 이상이면 작업할 필요가 없으므로 답은 0이다.

목표를 이루는 최소 작업 횟수를 구하라.

## [제약사항]

1. 4 ≤ N ≤ 1,000
2. 수열의 각 값은 절댓값이 100,000 이하인 정수이다.

## [입력]

첫 줄에 테스트 케이스의 수 T가 주어진다. 각 테스트 케이스는 두 줄로, 첫 줄에 N, 둘째 줄에 수열의 값 N개가 공백으로 구분되어 주어진다.

## [출력]

테스트 케이스마다 `#t`(t는 1부터 시작하는 테스트 케이스 번호)와 공백 한 칸 뒤에 최소 작업 횟수를 출력한다.

## 입력 예 / 출력 예

입력: [input.txt](input.txt) · 출력: [output.txt](output.txt)

| 케이스 | 입력 내용 | 정답 | 이유 |
|---|---|---|---|
| #1 | N=5, `2 -3 0 1 -1` | 2 | 합 −1 → 목표 10. +6, +5 |
| #2 | N=4, `3 3 2 1` | 0 | 합 9가 이미 8 이상 |
| #3 | N=6, `-5 0 -2 4 -1 -3` | 3 | 합 −7 → 목표 12. +9, +6, +6 |
| #4 | N=8, `-7 2 -10 0 5 -4 -6 1` | 3 | 합 −19 → 목표 16. +13, +13, +10 |

## 해설

i번에 작업했을 때 합이 늘어나는 양은 다른 칸과 상관없이 정해져 있다.

```
증가량[i] = max(A[i] + i, i) − A[i] = max(i, i − A[i])
```

| A[i] | 바뀐 값 | 증가량 |
|---|---|---|
| 0 이상 | A[i] + i | i |
| 음수 | i | i + \|A[i]\| |

**그리디:**

1. 합 S를 구한다. S ≥ 2N이면 답은 0.
2. 모든 칸의 증가량을 구해 큰 순서로 정렬한다.
3. 앞에서부터 더하다가 S ≥ 2N이 되는 순간의 개수가 답이다.

k번 작업할 때 합을 가장 크게 만드는 선택은 증가량 상위 k개다(더 작은 증가량을 골랐다면 더 큰 것으로 바꿔도 손해가 없다). 모든 칸에 작업하면 A[i] ≥ i이므로 합이 N(N+1)/2 ≥ 2N(N ≥ 4)이 되어 답은 항상 있다.

시간 복잡도: O(N log N)

### 자주 하는 실수

| 실수 | 결과 |
|---|---|
| 증가량을 i로만 계산 | 음수 칸의 큰 증가량을 놓침 |
| 번호를 0부터 계산 | 증가량이 1씩 작아짐 |
| 바뀐 값 기준으로 정렬 | 증가량 순서가 아니라 틀림 |
| 처음 합을 확인하지 않음 | 이미 만족하는데 1 이상 출력 |
